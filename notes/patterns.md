## Hash

看到：

- 判断某个值是否出现过
- 查找与当前元素配对的另一个值
- 按某种特征把元素分组
- 需要 O(1) 查询来避免排序或二重循环

优先考虑：

- `set`：只关心「在不在」
- `dict`：需要「key → 附加信息」，如下标、分组、计数

三种典型用法（Hot 100 Hash 三题）：

| 用法 | 题目 | key | value |
|---|---|---|---|
| 查配对 | 1. Two Sum | 元素值 | 下标 |
| 分组 | 49. Group Anagrams | 排序后的字符串 | 同组字符串列表 |
| 判存在 | 128. Longest Consecutive Sequence | 元素值 | 无，用 `set` |

要点：

- **先查后存**：需要「在当前元素之前出现过」的语义时，必须先查询再插入，否则会用到自己（Two Sum）。
- **key 必须唯一标识一类**：同组一定相同、不同组一定不同。字符和这类会冲突的量不能作 key（Group Anagrams）。
- **key 必须可哈希**：`list` 不行，要转成 `str` 或 `tuple`。
- **用 O(1) 查询换掉排序**：需要「x + 1 在不在」时，`set` 把 O(n log n) 的排序降到 O(n)（128）。
- **遍历去重后的集合**，不要遍历原数组，否则重复元素会带来重复计算（128）。

## Two Pointers

看到：

- 要求原地修改数组，且保持相对顺序
- 在有序（或可以先排序）的数组里找满足条件的两个数 / 三个数
- 从两端向中间收缩时，能说清「哪一边的剩余组合可以整体丢掉」
- 暴力是 O(n^2) 枚举数对，需要降一维

优先考虑：

- **快慢指针**：同向移动，`fst` 记录「下一个该写的位置」，`sec` 扫描
- **对撞指针**：`l`、`r` 从两端出发，每步根据比较结果丢掉一边
- **排序 + 固定一个 + 对撞**：k 数之和降成 (k-1) 数之和

几种形态（Hot 100 Two Pointers 四题）：

| 形态 | 题目 | 指针含义 | 移动依据 |
|---|---|---|---|
| 快慢 | 283. Move Zeroes | `fst`：下一个非零数的位置；`sec`：扫描 | `nums[sec] != 0` 时写入 / 交换 |
| 对撞 | 11. Container With Most Water | 左右边界 | 移动较矮的一边 |
| 排序 + 对撞 | 15. 3Sum | 固定 `a`，`l`、`r` 找 `-a` | 和小移 `l`，和大移 `r` |
| 对撞 + 维护最值 | 42. Trapping Rain Water | 左右边界，各带 `lmax`、`rmax` | 移动较矮的一边，它的水位已确定 |

要点：

- **快慢指针先回答两件事**：`fst` 表示什么；`sec` 位置的旧值去哪（补 0 还是交换）。用 `for sec in range(n)` 驱动扫描，边界问题自然消失（283）。
- **对撞指针要能证明丢掉的一边没用**：写出不等式，而不是凭感觉。11 题：高度不超过矮边、宽度更窄；3Sum：数组有序，和偏小时 `nums[l]` 和所有剩余的 `r' < r` 配对只会更小。
- **「移动较矮的一边」的共同原因**：矮的一边的结果已经能确定，高的一边还取决于中间没看过的元素。11 题是「矮边的剩余组合都不更大」，42 题是「矮边的水位就是它自己的最高值」，因为另一边真正的最高只会更高。
- **两遍扫描可以换成对撞**：42 题「左右各扫一遍求最值」需要 O(n) 空间；对撞时每次只处理结果已确定的一边，空间降到 O(1)。
- **判断必须互斥**：`if / elif / else` 三分支，漏写 `elif` 会让「不相等」落进「相等」分支（15）。
- **对称分支复制后逐个换变量**：移动 `r` 的循环要判断 `nums[r]`。11 题和 15 题犯了同一个错，结果都是死循环。
- **内层 while 必须带边界** `l < r`（11、15）。
- **排序后去重靠跳过相同值**：相同值挨在一起，保留第一个、跳过后面的，和前一个比；不需要 `set`（15）。
- **有序时尽早结束**：3Sum 中 `a > 0` 直接 `break`（15）。
- **`for i in range(n)` 里改 `i` 无效**：需要跳着走时用 `while`（15）。
- **常数优化看数据分布**：跳过相同值、交换代替补 0 等写法在某些分布下更快、另一些分布下更慢，复杂度不变，用本地实测决定（283、11）。

## Sliding Window

看到：

- 求满足条件的**连续**子串 / 子数组（最长、最短、全部位置）
- 条件可以随着两端移动**增量维护**（加入一个、移出一个）
- 暴力是枚举所有 (i, j)，O(n^2)

优先考虑：

- 两个指针**同向**移动，都只往右走，总共 O(n)
- 窗口状态用 `set` / `dict` 记录（字符集小时用定长数组）

两种形态（Hot 100 Sliding Window 两题）：

| 形态 | 题目 | 窗口状态 | 左端怎么动 |
|---|---|---|---|
| 长度可变 | 3. Longest Substring Without Repeating Characters | `last`：字符 → 上次出现的下标 | 重复字符还在窗口内时，跳到它的下一位 |
| 长度固定 | 438. Find All Anagrams in a String | 26 位计数数组 | 每步右移一格：移出 `s[i - 1]`，移入 `s[i + k - 1]` |

要点：

- **两端都只往右走**：任何移动左端的赋值，新位置都不能小于旧位置。3 题直接 `l = last[c] + 1` 会让左端退回，`'abba'` 出错；要先判断 `last[c] >= l`，或取 `max`。
- **全局记录 ≠ 窗口内**：`last` 这种字典不会随窗口移动删除旧记录，`c in last` 只说明出现过，要再和 `l` 比较（3）。
- **窗口长度 `r - l + 1`**：两端都包含（3）。
- **固定窗口先建第一个窗口，再逐格滑动**：每步只改移出和移入的两个位置，不要对每个窗口重新计数或排序；p 很长时后者是 O(n * k)（438）。
- **计数减到 0 要么删键，要么用定长数组**：`Counter` 相等比较在 3.9 和 3.10+ 行为不同（438）。
- **和对撞指针的区别**：对撞指针从两端往中间收缩，依据是「哪一边可以整体丢掉」；滑动窗口两端同向，依据是「窗口是否满足条件」。

## Subarray（子数组 / 子串）

看到：

- 求连续子数组 / 子串的个数、最值、最短最长
- 暴力是枚举所有 (i, j)，O(n^2) 以上

优先考虑：

- **前缀和 + 哈希**：和为定值的子数组个数，有负数时唯一可行的线性做法
- **单调队列**：定长窗口的最值
- **可变长度窗口**：条件随窗口扩张单调变好、随收缩单调变差时

三种形态（Hot 100 Subarray 三题）：

| 形态 | 题目 | 维护什么 | 关键 |
|---|---|---|---|
| 前缀和 + 哈希 | 560. Subarray Sum Equals K | `{前缀和: 次数}` | `pre[j] - pre[i] = k`，先查后存，初始 `{0: 1}` |
| 单调队列 | 239. Sliding Window Maximum | 下标队列，值单调递减 | 右端弹掉 <= 新数的，左端弹过期 |
| 可变窗口 | 76. Minimum Window Substring | `need` 计数 + `missing` | 右端扩到满足，左端收到不满足 |

要点：

- **有负数就不能用滑动窗口**：窗口和不再随两端移动单调变化，没有收缩依据，改用前缀和 + 哈希（560）。
- **「差等于 k」就是 Two Sum 的形状**：区别是这里要计数，所以哈希表存次数而不是「出现过」；空前缀 `{0: 1}` 对应从下标 0 开始的子数组（560）。
- **先查后存**：先存会把长度为 0 的空子数组算进去，只有 `k = 0` 会暴露（560）。
- **单调结构丢掉的是「又小又靠左」的元素**：它们更早过期且更小，永远轮不到（239）。
- **先确定 `i` 表示窗口哪一端**，两处弹出判断按同一基准写：右端用 `q[0] <= i - k`，左端用 `q[0] < i`（239）。
- **可变窗口的收缩循环**：`while 满足条件: 更新答案; 移出 s[l]; l += 1`。判断放循环条件、更新答案放在移出之前，退出时 `l` 正好停在边界，不需要补偿（76）。
- **条件判断尽量 O(1)**：维护一个计数（`missing`、达标字符数）代替每步全扫计数表，n = 10^5 实测差一个量级（76）。
- **用 `deque` 而不是 `list`**：`list.pop(0)` 是 O(k)（239）。

## Array（数组原地技巧）

看到：

- 要求原地修改、O(1) 额外空间
- 答案只和「每个位置的左边 / 右边」有关
- 值域和下标范围能对上（值在 [1, n] 内）
- 区间、旋转、重排这类整体性操作

优先考虑：

- **一次扫描的递推**：以当前元素结尾的最优解（Kadane）
- **前缀 / 后缀信息**：两趟扫描，先存一侧再乘（加）另一侧
- **排序 + 相邻比较**：区间合并
- **反转 / 交换归位**：旋转、原地哈希

五题的形态：

| 形态 | 题目 | 关键 |
|---|---|---|
| 递推 | 53. Maximum Subarray | 前面那段为负就丢掉，从当前元素重新开始 |
| 排序 + 扫描 | 56. Merge Intervals | 排序后能合并的一定相邻；右端取 max |
| 三次反转 | 189. Rotate Array | k %= n；整体反转再分别反转两段 |
| 前后缀积 | 238. Product of Array Except Self | 左积 * 右积，天然绕开 0，不用除法 |
| 原地哈希 | 41. First Missing Positive | 答案在 [1, n+1]；把值 v 换到下标 v-1 |

要点：

- **原地修改要改内容不是改名字**：`nums = ...` 只重新绑定局部变量，`nums[:] = ...` 才会改到调用方的列表（283、189）。
- **答案初值别用 0**：子数组 / 子序列非空时，全负输入会错（53）。
- **特判之前先想通用公式**：238 给 0 写了三个分支，其实前后缀积天然覆盖；特判越多，要维护的不变量越多。
- **循环条件里不要藏线性操作**：`min()`（128）、`nums.index()`（238）、`set(nums)`（41）都把 O(n) 变成了 O(n^2)。
- **交换前先把目标下标存进变量**：Python 多重赋值是右边先求值、左边从左到右赋值，`nums[i], nums[nums[i]-1] = ...` 的第二个下标会用到改过的 `nums[i]`（41）。
- **归位型循环的条件看「目标位置」**：写成「当前位置不对」遇到重复值会死循环（41）。
- **Python 里省空间不等于快**：切片 / 拼接在 C 层完成，三次反转的逐个交换反而慢一倍（189）。

## Matrix（二维数组）

看到：

- 要求原地修改二维数组
- 按某种几何顺序（螺旋、旋转、对角）遍历或重排
- 行、列各自有序，要在二维上查找

优先考虑：

- **先记录、后修改**：标记要清零的行列，或把标记存进矩阵自身
- **几何分解**：旋转 = 转置 + 反转；螺旋 = 分层剥壳
- **利用有序性走阶梯**：从「一边变大、一边变小」的角出发

四题的形态：

| 形态 | 题目 | 关键 |
|---|---|---|
| 原地标记 | 73. Set Matrix Zeroes | 先记录行列集合；O(1) 版把标记存进首行首列，最后才回填它们 |
| 分层剥壳 | 54. Spiral Matrix | 四个边界向内收；后两条边要二次判断边界 |
| 转置 + 反转 | 48. Rotate Image | 转置只走一半（`j < i`）；每行反转减半的是列下标 |
| 阶梯查找 | 240. Search a 2D Matrix II | 从右上角出发，大了往左、小了往下，O(m + n) |

要点：

- **原地修改时，新写的值不能被后续读取当成原始数据**：73 边扫边清零会把刚写的 0 当成原始 0（示例一得到全 0 的下半部分）。
- **借矩阵自身当存储时，被借走的那一行 / 一列要先单独记状态、最后才回填**（73）。
- **交换一对元素的循环，被减半的是真正配对的那个下标**：转置配对 `(i,j)`/`(j,i)`，每行反转配对 `(i,j)`/`(i,n-1-j)`（48）。
- **剥壳剥到只剩一行或一列时会重复走**，后两条边前面要再判边界（54）。
- **`matrix[r] = ...` 换掉的是外层列表的元素，`matrix[r][:] = ...` 才是改行内容**（73、48、189）。
- **负数下标是陷阱**：`-0` 等于 `0`，`matrix[-i]` 在 `i = 0` 时指向第 0 行（48、189）。
- **答案是路径时就用路径生成**，不要拆成两个维度再组合（54 第一版的笛卡尔积）。
- **有序矩阵的查找要从「一边增一边减」的角出发**，左上 / 右下两个角无法定向（240）。
- **规模小到计时失效时，用「访问次数」验证复杂度**：`list` 子类统计 `__getitem__` / `__contains__`（240）。

## Linked List（链表）

看到：

- 输入是链表头节点，要改连接：反转、交换、删除、合并、排序
- 要找中点、倒数第 n 个、环、入环点、两条链的交点
- 要求 O(1) 额外空间（不能把节点倒进 list）
- 要 O(1) 增删、又要按使用顺序排队（设计题）

优先考虑：

- **虚拟头节点**：头节点可能被换掉、被删掉，或者「第一个节点接在哪」要单独处理时
- **快慢指针**：中点（234、148）、判环和入环点（141、142）、间隔 n 找倒数第 n 个（19）
- **两个积木**：原地反转（206）用在 234 后半段、25 每一组；有序合并（21）用在 148、23
- **哈希表配合链表**：原节点 → 拷贝（138）、key → 节点（146）、存走过的节点（141、142 的 O(n) 解）

十四题的形态：

| 形态 | 题目 | 关键 |
|---|---|---|
| 双指针换头 | 160. Intersection of Two Linked Lists | 走到尽头换到另一条，两人都走 m + n 步，比节点用 `is` |
| 原地反转 | 206. Reverse Linked List | `prev` / `cur` / 先存 `nxt`；递归版要 `head.next.next = head` 再断开 `head.next` |
| 中点 + 反转后半 | 234. Palindrome Linked List | 快慢指针找中点，反转后半段两头比；要处理每个节点就写 `while cur` |
| 快慢指针判环 | 141. Linked List Cycle | 同时出发，先移动再比较；`fast is not None and fast.next is not None` |
| 入环点 | 142. Linked List Cycle II | `a = (k-1)(b+c) + c`：相遇后一个回 `head`，同速走，第一次相等就是入口 |
| 有序合并 | 21. Merge Two Sorted Lists | `dummy` + `tail`，`while a and b`，循环后一行接上剩余 |
| 逐位相加 | 2. Add Two Numbers | 用完的一边当 0，`carry` 放进循环条件 |
| 间隔 n | 19. Remove Nth Node From End of List | `dummy` 出发，`fast` 先走 n 步，`slow` 停在要删节点的前一个 |
| 两两交换 | 24. Swap Nodes in Pairs | 尾插：每次接 `second` 再接 `first`，循环后接落单的 |
| 分组反转 | 25. Reverse Nodes in k-Group | 每组反转后接到上一组尾巴；不足 k 个的不反转（或反转回来） |
| 深拷贝带随机指针 | 138. Copy List with Random Pointer | 字典两遍；O(1) 版三遍：交错插入、接 `random`、拆分 |
| 归并排序 | 148. Sort List | 自顶向下递归 O(log n) 栈；自底向上 `step` 翻倍，O(1) |
| 多路归并 | 23. Merge k Sorted Lists | 最小堆放 `(val, i, node)`，下标打破平局 |
| 字典 + 双向链表 | 146. LRU Cache | 两头哨兵；只在 `remove` / `add_front` 里改指针；节点存 `key` |

要点：

- **改指针之前，先存下后面还要读的值**：206 先存 `nxt`；25 剩余部分先断开再取 `next` 拿到 `None`；138 先改 `copy.next` 再读 `cur.next.next`，原链表被破坏；146 摘下节点漏改一侧，`get` 后链表成环。多个指针赋值时逐行问「这一行读的东西，前面有没有改过」。
- **循环条件取决于结束时指针要停在哪**：处理每个节点、最后停在 `None` 写 `while cur`；要停在最后一个节点上继续用写 `while cur.next`。234 多写了 `.next` 漏掉最后一个，148 少写了 `.next` 走过了头。
- **快慢指针三件事**：同时出发就先移动再比较（142 把比较放进循环条件，一步没走）；`fast` 的起点决定 `slow` 停在哪（从 `head` 出发是后半段开头，从 `head.next` 出发是前半段末尾），改了起点断开方式要跟着改（148）；无环判断要和循环条件对应，或者用 `while ... else`（142）。
- **虚拟头节点消掉「第一个节点」的特判**，循环后一行接上剩余部分消掉「某一边用完」的特判：21、2、19、24、138 都是这样从多分支缩成一个循环。写出执行不到的代码（21、19、138）往往就是特判太多的信号。
- **比节点用 `is`、映射用节点对象当键**，不要按 `val`：值重复时会找错（160、142、138）。
- **`=` 左边是裸名字只改这个名字的指向**：148 的 `small = small.next` 移动不了 `left`，23 的 `heads = lists` 不是副本、改了调用方的 list。
- **双向链表挪一个节点要改 6 个指针**：摘下 2 个、插入 4 个。拆成 `remove` / `add_front` 两个方法，其他操作都由它们组合（146）。
- **改不改输入要看题目**：141 标记 `val` 能过但破坏输入；142 明确禁止修改；138 交错插入后必须拆回原样。
- **递归深度是 Python 的硬限制**：默认 1000，206、25 的递归版要放宽到 1 万；234 放宽到 20 万处理 10 万个节点会段错误；148 把合并写成递归深度是 n，5 万个节点 `RecursionError`。
